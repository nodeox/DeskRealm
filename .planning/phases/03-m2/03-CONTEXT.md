# Phase 3 · M2 受管连接与策略

**日期** 2026-11-22
**状态** 可执行规划
**基线** `3a42e9c`，M0 和 M1 开发验证结束

## 阶段边界

交付 Go 中心、受管 Windows 主控端与受控端、受管会合入口和中文控制台。直连与单个配置中继共用会话准入、核销、权限、租约及撤销。中心保存真实路径、策略回执和会话审计。M3 处理多区域选点、中继部署、品牌签名发布及升级。Phase 5 按约定先验证 Linux 中心及一台中继，再用两台 Windows 验证注册、直连、强制中继和重建后沿用原公钥，然后扩展到受管会话验收。阶段开发使用自动化、隔离夹具和构建执行证据。

## 文档已确定的约束

- **D-01** 管理授权、连接 ACL、会话操作分别执行。后台管理员角色只授予后台管理范围。中心根据当前用户、两端设备、可信版本、归属组和用途判定准入。无匹配许可时拒绝，显式拒绝优先。通讯录入口重查册和设备权限，再走相同 ACL。
- **D-02** 设备 UUID 绑定有效设备公钥，RustDesk ID 用于寻址。中心签发短期授权，受管会合入口校验协调请求，受控端验证授权和安全通道内的主控持钥证明，再在线向中心核销。同一连接的幂等请求可重试，一份授权只可被一个连接核销。
- **D-03** 受控端以授权、控制角色、设备策略和适用本地确认的交集执行画面、键鼠、音频、剪贴板和文件传输。有人值守默认在受控端确认；无人值守需要有效策略明确批准设备和用途。受管包只开放能执行同等校验的入口。
- **D-04** 初始授权 60 秒、租约 30 秒、续租间隔 10 秒作为开发初值。终端以单调时钟限制会话，睡眠恢复先复核。停用、撤销和权限收缩停止续租。UI 分别呈现已请求、等待租约到期及真正收到端点断开回执。在线撤销 5 秒及失联停止控制 35 秒留待 Phase 5 测量。
- **D-05** 策略版本不可改写，选择顺序为设备、归属用户、主设备组、组织默认。支持灰度、应用失败反馈及回滚来源。期望版本和端点应用版本分别呈现。使用事务保证授权、续租、撤销、业务审计及 outbox 一致。
- **D-06** 中文控制台和端点沿用设计文档与原型。有权限的管理员操作策略和撤销；运维可查看本人会话；审计员仍按已授范围读取审计。签发、核销与设备事件使用同一会话 ID，禁止日志和 UI 暴露票据、私钥及会话内容。

## 规划采用的实现选择

- **D-07** 以 RustDesk 客户端 `1.5.3` 和 Server OSS `1.1.16` 的发布 Git ref 为受管源码起点，固定各子模块并维护独立补丁和取证脚本。M0 的已固定镜像是原版试点基线。受管入口使用独立配置，先从单中继和直接模式贯通。
- **D-08** 复用 M1 账号、设备密钥及 PostgreSQL 事务。以一次性设备持钥挑战绑定短期设备运行会话和用户登录身份，后台 API Token 保持仅面向账号读取。会话授权签名用独立持久密钥和 `kid`，同一部署重启后保留验证公钥。具体格式及会话证明字段在 03-01 固定，以互操作夹具验证 Go 与 Rust。
- **D-09** 多条允许规则以完整的单条规则评估用途、动作上限和关联控制角色。先执行任何匹配的拒绝，再使用可授予完整请求集合的规则。中心在签发、核销和续租重查必要状态及策略；不能确认有效应用的策略不授予其新增能力。M1 通讯录解析抽取可在同一写事务调用的帮助函数，保留现有公开解析入口。
- **D-10** Windows x64 和 ARM64 分别记录源码、编译器、构建状态及适用证据。开发环境缺少原生构建能力时记录缺失的验证与可复跑命令，保留对应门禁为待完成。主机 Rust 测试、网络夹具、Windows 制品和目标环境结果各自取证。
