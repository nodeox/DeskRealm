## Phase 5 验收保留

M0–M3 开发完成后执行用户指定顺序。Linux 中心和一台中继先验，随后双 Windows 核对注册、直连、强制中继和重建后沿用原公钥。在线撤销 5 秒内获得受控端实际停止回执、链路隔离后 35 秒内终端实际停控，以端点取证核对，覆盖真实两路和睡眠恢复。

## 已验证的开发步骤

2026-11-22，03-01 Task 1 的 `bash scripts/deskrealm-m2-test sources` 通过。两个固定上游仓库及子模块由空目录重新取回。移动标签、错版子模块和脏工作树均被拒绝，夹具补丁可重放。Go 与 Rust 对 5 个签名向量及 13 个拒绝用例结果一致。Rust 使用固定镜像内的 Linux ARM64 工具链。实际受管补丁、Windows 原生构建和目标拓扑仍待相应计划验证。

03-01 Task 2 在提交 `9cca7a7` 通过 `identity` 和 M1 `all`。测试验证设备批准与持钥、并发核销、防重放、错端、有效期、钥匙轮换、禁用、主控同登录绑定、原会话撤销、管理令牌隔离、心跳过期、事务回滚和日志脱敏。以临时 PostgreSQL 连续启动两个本机 `serve` 进程，复用同一签名种子文件，观测到不变的 `kid` 和公钥。无签名配置的进程响应 503。会话准入和受管 Windows 行为留待后续计划。

03-02 Task 1 在提交 `c9122ee` 通过 `rules`、`identity` 和 M1 `all`。两个具名 ACL PostgreSQL 竞态用例验证默认拒绝、显式拒绝优先、允许动作不可拼接、非管理员拒绝、草稿发布与并发编辑、旧角色版本失效、实时撤销用户组和通讯录权限、心跳超时及协议版本、审计和业务事务回滚。身份回归的凭据期限断言改用 PostgreSQL 时钟，避免宿主机与容器时钟偏差。版本化设备策略和设备应用回执随后由 Task 2 验证。

03-02 Task 2 在提交 `4ca819a` 通过 `policies`、`rules`、`identity`、`vectors` 和 M1 `all`。真实 PostgreSQL 竞态测试覆盖四级分配、并发修订、灰度基线及稳定分桶、兼容回滚、签名和错端拒绝、部分设备失败及按设备重试、策略撤除、回执幂等与乱序、密钥轮换、无人值守用途和审计事务回滚。Go 与 Linux ARM64 Rust 对 7 个签名向量及 15 个拒绝用例结果一致。

03-03 Task 1 在提交 `43cba08` 通过 `sessions`、`vectors`、`rules`、`policies`、`identity` 和 M1 `all`。两个具名 PostgreSQL 竞态测试覆盖默认拒绝、策略求交、目标与密钥绑定、签发期限、幂等同签名、ACL 归档与会合竞争、两端签名及有人值守确认、独立中继配对、双连接竞争、精确重放维持原 30 秒租约、签发和核销的审计失败回滚。Go 与 Linux ARM64 Rust 对 8 个签名向量及 17 个拒绝用例结果一致。续租与实际停止回执留待 Task 2，实际连接及路径取证留待 03-04。
