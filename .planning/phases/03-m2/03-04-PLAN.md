## Task 1 接续点

- 已落地共享原生签名帧、会合与端点 protobuf、TCP 方向密钥通道绑定，以及中心对目标 RustDesk ID 的绑定检查。可从锁定源码用 `native-wire` 复验。
- 已在 `src/rendezvous_server.rs` 和 `src/relay_server.rs` 接入独立挑战、中心复查和配对放行，并用 `native-coordination` 验证真实服务进程。
- 已在 RustDesk 客户端的 `libs/base` 实现中心签发、真实两路 TCP 协调、方向密钥协商、双方证明、本地确认接口和受控端在线核销。用 `native-admission` 验证这些代码与真实 `hbbs` 和 `hbbr` 互操作。
- `src/client.rs`、`src/rendezvous_mediator.rs` 和 `src/server.rs` 已接入受管原生库、设备持钥认证、策略应用与签名回执。Windows 有人值守确认发往当前解锁的物理控制台。受管模式拒绝原版会话入口；核销后的 TCP 流暂时关闭并向中心报告实际关闭。

## Task 2 接续点

- RustDesk `base` 原生端点库已提供按能力检查、续租、连接状态查询和带类型的停止回执。核销及续租使用计入系统睡眠的本地截止时间，重试复用首次请求时间，旧租约到期后拒绝迟到响应。
- 接续在同一加密流上接入实际操作，配置独立的续租和撤销轮询。受控端必须在订阅服务、消息入口、队列消费和清理处检查权限及本地截止时间，完成清理后再上报停止。桌面入口当前仍在核销后关闭连接。Windows 完整构建及实际弹窗验证仍须取证。
