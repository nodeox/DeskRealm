# 端域 DeskRealm

## What This Is

端域是面向企业和团队的自托管远程桌面与终端管理平台。管理员通过中文 Web 控制台部署中心和区域中继、管理身份与设备、签名发布 Windows 客户端，并查看会话、任务和审计结果。运维人员从获授权的设备列表或通讯录连接 Windows 终端，受控端执行访问确认、会话权限和撤销。

## Core Value

管理员能在自有基础设施上完成从部署、签名发布到终端纳管的流程，运维人员能安全连接获授权的设备，管理员能撤销会话并追溯结果。

## Requirements

### Validated

暂无。当前仓库包含设计资料，首版功能等待实现与验收。

### Active

- [ ] M0 安装和传输基线。固定 RustDesk OSS 版本，提供 Linux 中心与单中继的部署原型、持久身份和可复跑的连接记录。
- [ ] M1 用户、设备和管理面。交付本地登录、TOTP、OIDC、用户和设备生命周期、分组委派、API Token、通讯录、设备审批、中文控制台、审计查询和可恢复任务基础。
- [ ] M2 受管会话和策略。两端受管客户端对直连和中继使用一致的连接准入和受控端核销，执行有人值守确认或经批准的无人值守、独立操作权限、续租、撤销和策略回执。
- [ ] M3 部署和自动化交付。交付中心正式安装、区域中继接入与双端 RTT 自动选点、签名构建、分组发布、免填配置、设备入网、灰度升级、备份恢复及兼容回滚。
- [ ] 完成兼容和迁移。依据固定版本验证原版试点，并用授权导出样本验证导入、映射、作用域和回切。
- [ ] 首版开发完成后进行目标环境验收。先验证 Linux 中心和一台中继，再用两台 Windows 终端验证注册、直连、强制中继与服务重建后沿用原公钥。随后核对受管会话、双区域选点、签名发布、安装和恢复等首版验收场景。

### Out of Scope

- 浏览器主控、原生 LDAP、邮件验证和邮件恢复、更多终端平台、集中录像及高级会话能力归入 M4，按平台和能力单独验收。
- 多组织共享单一实例和中心多活超出首版部署模型。首版每实例服务一个组织，采用单活中心和备份恢复。

## Constraints

- **部署与技术栈。** Linux Docker Compose、Go 控制面、PostgreSQL、Vue 与 TypeScript 中文控制台。传输与会合沿用 RustDesk OSS，Windows 为首版受管主控和受控平台。支持的架构以验收结果为准。
- **身份和权限。** 管理授权、连接准入、受控端操作权限各有执行点。默认拒绝未获授的连接。直接路径和中继路径都要求受控端确认有效授权并按租约约束操作。
- **发布安全。** 公共安装包包含经验证的中心连接配置。设备入网凭据按部署对象单独发放。签名和摘要校验通过后才能向获授权组发布，并记录源码、模板与产物来源。
- **恢复。** 重试和重建保留中心身份与业务状态。任务可按对象恢复，重复提交和回执可去重。
- **验收。** 开发阶段使用构建、自动化测试和可复跑检查。Linux 中心、中继和双 Windows 的目标环境验收集中在首版开发完成后。在线撤销回执 5 秒及失联停止控制 35 秒保留为文档中的真机验收目标。

## Key Decisions

| Decision | Rationale | Outcome |
| --- | --- | --- |
| 文档采用 RustDesk 客户端 1.5.3 和 Server OSS 1.1.16 作为初始基线 | 固定兼容验证对象。Pro 1.8.8 作为公开能力对标 | 待实现及验证 |
| 中心持有授权和策略，受控端执行会话权限 | 直连和中继共享同一授权及撤销语义 | 待实现及验证 |
| 区域中继按合规候选的双端 RTT 之和选点 | 基于两端实际可达性与测量，采样不足时按站点或 GeoIP 回退 | 待实现及验证 |
| 用户指定先开发，再进行 Linux 与双 Windows 实机验收 | 先准备首版实现和可复跑步骤，之后在目标环境集中验收 | 已确定顺序，验收待执行 |

## Evolution

每个阶段结束时更新功能状态、证据和决策。将通过目标环境验收的功能转入已验证，并注明阶段和证据来源。范围变化应同步到需求及路线图。

首版结束时复核核心价值、后续范围、架构支持矩阵和目标环境数据，并用验收结果更新发布范围。
